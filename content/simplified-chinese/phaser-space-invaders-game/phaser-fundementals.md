## 第 1 部分：Config 变量

让我们来了解一下 Phaser 的基础知识，这是一款使用 HTML 和 JavaScript 构建网页游戏的游戏框架！这是你将在本次工作坊中学习使用的工具。

打开 `game.js` 文件。每个 Phaser 游戏都会从一个存储游戏配置的变量开始（通常名为 config，就像我们这里使用的那样）。

```javascript
var config = {
  type: Phaser.AUTO,
  width: 512,
  height: 544,
  backgroundColor: 0x000000,
  scene: [Scene1, Scene2],

	physics: {
        default: 'arcade',
        arcade: {
            gravity: { y: 0 },
            debug: false
        }
    },
};
```

在这个变量中，你会注意到我们定义了一些关于游戏的特性，比如宽度、高度和背景颜色。我们还定义了将在游戏中使用的场景（稍后会详细介绍场景）。你还可以不使用场景，直接将所有代码写在 `game.js` 文件中。

你会注意到我们也在 Config 中定义了游戏的物理特性。在游戏设计中，物理是定义游戏“手感”的最关键部分之一。例如，《马里奥》中弹跳的物理效果赋予了它独特的“马里奥感”。在我们的游戏中，你可以看到我们使用了 Phaser 中一种简单易用的物理类型——“arcade”物理。注意我们将重力设置为 0，因为我们的游戏是一个太空射击游戏，不需要有任何重力将角色向下拉。

在 `game.js` 文件的末尾，你可以看到我们将 config 变量传递给了一个游戏变量，这是 Phaser 游戏中几乎必需的内容。

## 第 2 部分：场景

现在，让我们稍微聊聊场景。一个场景本质上是用户操作的一种游戏状态。通过例子可以更好地理解这一点：

以著名游戏《精灵宝可梦》为例。当你玩游戏时，通常会在世界中探索。当你在草丛中遇到训练师或野生精灵时，你会进入一个不同的场景进行战斗。战斗完成后，你可能会打开地图查看前往的方向——这又是打开了一个不同的场景。这三个场景的功能完全不同，并且有各自附加的机制。当你退出地图时，游戏会切回到玩家可以探索的世界场景。而当你进入战斗时，又切换到了战斗场景。可以看到，这三个游戏状态的创建方式完全不同——战斗需要菜单，世界需要 2D 空间和一个玩家，地图则基本是一个交互式图表。我们将它们分成不同的场景，因为它们的创建方式完全不同。

你可以将玩家看作是在游戏中穿梭于不同的场景。他们一次只能使用一个场景，而每个场景几乎像是一个独立的小型游戏（尽管通常会有一个主要场景，并不完全是“小型”的）。

{{% notice info %}}

从技术上讲，如果你愿意的话，我们可以为这三个游戏状态使用单一场景（如何将游戏划分为场景取决于游戏设计师）。理论上是可以做到的。然而，创建单独的场景会让编码变得简单得多（就本例而言，我甚至无法想象如何将它们塞进一个场景，而不是简单地将一个场景的视觉内容覆盖到另一个场景上）。
{{% /notice %}}

另一个非常常见的场景使用例子是：标题画面。

![Outliers 游戏标题屏幕](../media/title-game.png)

第一个场景通常只展示一个标题屏幕，其中可能包含设置、加载存档等内容。一旦玩家点击“开始游戏”，会切换到另一个场景，在那里他们可以真正开始玩游戏。

我们要做的正是这样。场景 1 将包含一个标题屏幕，而场景 2 将包含我们的实际游戏玩法。因此，场景 2 将包含大部分代码，也是你完成主要工作的地方。

# 第 3 部分：无限画布

当你在 Replit 上启动游戏时，你会在屏幕上看到一个空白画布，你最终需要在上面放置一些内容。然而，你看到的仅仅是整个画布的一部分——实际上，画布在各个方向上都是无限的。画布在所有区域的行为都是一致的——这意味着对象可以移动并被放置在用户无法看到的画布部分中。这会变得很重要，因为对于我们的游戏来说，我们并不希望游戏对象跑到屏幕外太远，因此我们需要将对象限制在屏幕内，或者当它们离开屏幕后将其删除。
