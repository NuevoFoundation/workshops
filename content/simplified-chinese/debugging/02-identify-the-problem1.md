## 编译器错误

让我们开始，来看看初学编程者面临的第一个令人畏惧的问题之一：**阅读**和**理解**错误。

错误分为两类：**编译器**错误和**运行时**错误。

**编译器**错误通常表示语法上的问题。也许你想在程序中表达一个想法，但没有遵守编程语言的规则。这些错误在编译程序时会被捕获。编译器错误相对容易修复，因为编译器（例如 `gcc`）通常会提供大量关于代码编译时发生了什么错误的信息。让我们来研究一些这样的错误。

在下面 Replit 程序中的 **Shell** 选项卡中打开并运行以下命令：

```bash
make CompilerErrors
```

{{% notice note %}}
在此示例中，我们不会运行程序 —— 该程序旨在展示一些你可能遇到的常见编译器错误。
{{% /notice %}}

<a class="my-2 mx-4 btn btn-info" href="https://replit.com/@nuevofoundation/Debugging-Samples-C" target="_blank">启动 Replit</a>

第一个错误应该如下所示（或类似）：

![错误 1：缺少分号](../resources/w2-01.png "编译器错误截图，提示 'error: expected ';' after top level declarator'")

你会注意到错误信息包含：

- 我们尝试编译的文件名称（**`CompilerErrors.c`**）。
- 发现错误的行号（**`12`**）。
- 在该行中发生错误的位置（**`19`**）。

如你所见，编译器提供了错误发生的代码行并指出了错误具体在哪里！它随后给出错误的简要说明 —— 在本例中，编译器期望在行尾添加一个分号（**`;`**）。简单地添加一个分号就可以修复这个错误。

另一个错误提到缺少一个大括号（**`}`**），而它并未预期有多余的大括号。这个问题的修复也相对简单：可以在 `func()` 旁边添加对应的左大括号 `{`。

{{% notice warning %}}
缺少大括号经常是看似奇怪错误的原因。编译器并不擅长指出大括号应该放在哪里，所以如果某个头文件缺少大括号，它会让错误变得混乱。在几乎所有情况下，当编译器输出大量你没有编写的代码中的错误时，大概率是某个地方（或者甚至是库的代码中）缺少大括号！
{{% /notice %}}

修复后，你可以使用相同的命令再次编译代码。

```bash
make CompilerErrors
```

等等，还有更多错误！正如警告框中提到的，如果缺少大括号，编译器并不擅长发现其他错误。编译器错误可能会“隐藏”其他错误。

我们将使用一个表格来展示常见编译器错误及其一般原因。

| 错误 | 原因 | 一般修复方案 |
|---|---|---|
| 缺少分号 | 缺少分号。 | 添加分号 `;`。 |
| 预期函数体在函数声明之后 | 函数体声明开头通常缺少大括号 `{`。 | 在需要的地方添加大括号 `{`。 |
| 预期标识符或 '(' | 在大括号相关的上下文中，通常意味着有多余的悬挂大括号 `{`。 | 删除多余的大括号或在之后添加对应的 `}`。 |
| 重定义 ... | 你的代码中某处声明了一个变量，然后再次声明了它。 | 重命名变量，或者删除其中一个声明。 |
| 使用未声明的类型 ... | 编译器找不到你想使用的类型的声明。 | 通常是因为不正确的 `#include` 指令（由于类型通常在头文件中声明）。检查是否有拼写错误。 |
| 必须使用 `struct`（或 `enum`）标签 | 在 C 中，你需要使用 `struct TYPE_NAME` 或 `enum ENUM_NAME` 来引用结构体/枚举类型。 | 通常 C 开发者会使用 `typedef` 声明，这样他们就不必每次都写 `struct` 或 `enum`。你可以自己添加这些关键字。 |
| 找不到指定成员 ... | 在你的 `struct` 中，没有你请求的字段名称。 | 可能是拼写错误，或者你还没有在 `struct` 中定义该字段。 |
| 类型不兼容 ... | 你混用了不兼容的类型，这在 C 中没有显式转换是不允许的。 | 检查赋值是否正确，或者使用显式类型转换静默掉编译时的错误。不过这可能会导致运行时错误。 |
| 参数类型不完整 | 如果一个函数返回 void，你不能将其作为参数传递给另一个函数！ | 将函数声明修正为非 void，并确保你真的需要这样的行为。 |
| 多余的 '(' 或 ')' 位于 ';' 前 | 括号 `()` 不匹配 | 某处多余了一对括号。仔细检查以确保每对括号都是成对的！ |

如果应用通用修复不起作用，**然后**你应该转向互联网寻求帮助。对于简单修复的常见错误，了解如何阅读错误并理解它需要修复的内容，通常要比上网查问题要快得多。

{{% notice warning %}}
并非所有编译器都能提供有用的信息。例如，C++ 的编译器错误可能会从非常简单的小问题（如 `CompilerErrors.c` 中的例子）变成大量的文字块，尤其是涉及模板时。本节的目的是 NOT 完全让你远离互联网资源，而是让你对它们有足够熟悉感，从而在修复简单错误时有一定的直觉。
{{% /notice %}}
