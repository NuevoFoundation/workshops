## 调试器

调试代码是一个如此普遍、常见的问题，人们已经构建了整个程序来帮助其他程序员更高效地调试。这些被恰当地称为 **调试器**，而且针对 C 编程语言有许多可用的调试器。让我们来看看 `gdb`，这是一种常用于命令行的调试器。

<a class="my-2 mx-4 btn btn-info" href="https://replit.com/@nuevofoundation/Debugging-Samples-C" target="_blank">启动 Replit</a>

在我们的示例中，我们将使用 <a href="https://www.youtube.com/watch?v=SLauY6PpjW4" target="_blank">快速排序 (Quicksort)</a> 算法。

**快速排序** 是一种通过在数组中选择一个元素作为 `基准` 来对数组进行排序的算法。

接下来，元素会根据以下两种条件进行组织：
- 小于基准的元素。
- 大于基准的元素。

排序完成后，以基准为中点，在数组的上下分区中递归调用相同的过程。

{{% notice note %}}
我们的快速排序版本假设最左边的元素是 "较大" 的元素，分区内最右边的元素是基准。
{{% /notice %}}

|:--:|

[GDB (GNU 工程调试器)](https://sourceware.org/gdb/) 是一个强大的调试器，可以让您从命令行调试程序，这在您无法访问 GUI（图形用户界面）时非常有用。

了解程序的工作原理对于有效调试至关重要。我们的 'quicksort' 实现运行的是快速排序的递归实现，如果当前元素小于基准，则执行排序，并假设第一个元素是 "较大" 的元素。排序本身发生在 `partition` 函数中。

### 使用 GDB 进行调试的步骤

#### 编译程序

1. 打开 **Shell** 选项卡并编译程序：

```bash
make Quicksort
```

{{% notice note %}}
在程序编译时，使用了参数：`-g` 和 `-Og`。第一个参数告知编译器添加 **调试信息**，这意味着如果没有这个参数，gdb 将无法调试程序。第二个参数告诉编译器以一种不会影响程序运行结构的方式对程序进行优化。如果没有 `-Og`，编译器可能会优化掉您的一些代码，因此调试器的效果可能会大打折扣。

注意第二个参数对于调试的重要性。对于调试，您应该 **始终** 确保编译器对代码的优化最小，因为优化可能会极大地改变代码的运行方式！
{{% /notice %}}

#### 运行程序 

1. 输入指令 `gdb examples/Quicksort`。这将打开 GDB 命令行界面。要使用 `gdb` 调试程序，您可以使用命令 `gdb <program name>`。

2. 确保 GDB 显示 `Reading symbols from ./examples/Quicksort...`，否则表示您未将程序附加到 GDB。

3. 您可以通过输入命令 `quit` (或其任意前缀：`q` 可以工作) 退出 GDB，就像普通的 shell 命令行一样。

#### 调试程序

要调试程序，我们需要从 GDB 运行它。

1. 输入命令 `run`（或 `r`）。这将执行程序，就像从普通命令行运行它一样。
```bash
(gdb) run
```

程序首先会打印出需要排序的数组的内容：一个无序数字数组。接下来，它会运行排序算法，最后打印出排序后的数组。您可以看到排序期间数组的变化！

然而，似乎排序并没有按预期进行。

让我们使用调试器提供的最重要工具之一：**断点**。断点告诉调试器每当程序运行到该行代码时暂停。这样您就可以实时查看程序中的变化。请注意，调试器在继续执行程序之前不会运行设置断点的代码行。

首先，我们来确定元素排序的所有操作发生的位置。您知道排序在哪里发生的吗？
{{% expand "***答案***" %}}
排序发生在 `for` 循环中，以及最后在基准与 "较大" 元素相互交换时。
{{% /expand %}}
<br/>

2. 使用语法 `break <filename:line>` 设置排序发生的断点。
{{% expand "***答案***" %}}
```bash
(gdb) break quicksort.c:27
``` 
{{% /expand %}}
<br/>

3. 使用 `run` 运行程序，观察程序在运行到断点时会暂停。

4. 程序暂停时，您可以查看变量的值。尝试一些 `print` 语句来对表达式进行评估。例如，以下是如何使用 `print` 语句：
```bash
# 您可以打印出变量的值
print myVariable

# 您可以通过完整的表达式创建更复杂的打印语句
print myVariable + 2 
```

5. 您可以通过调用 `next` (或 `n`) 手动逐步执行代码，这会告诉调试器前进到下一行代码 **而不跳入函数调用**。

6. `step` 命令会将调试器移动到函数调用中的第一行代码。

您需要找到导致程序无法按预期工作的错误变量。尝试查看是否能发现问题！
