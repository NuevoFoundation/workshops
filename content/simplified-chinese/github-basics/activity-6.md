### 合并冲突的挑战

想象一下，你正在与团队合作开发一个项目。你的任务是更新项目的网站，但当你尝试推送修改时，却遇到了合并冲突。这正是你技能经受考验的时候！

### 理解 GitHub Issues（问题）

在我们深入解决冲突之前，先来探索一个在协作编码中至关重要的工具：GitHub Issues（问题）。它不仅仅是错误报告，它是你项目的沟通中心。

### 测验：GitHub Issues 中标签的目的是什么？

花点时间考虑以下选项：

1. 用于将问题分配给团队成员  
2. 用于为问题设置到期日期  
3. 用于对问题进行分类和过滤  

想一想你在项目中使用 GitHub 的经验。哪一个功能最符合标签的目的？

准备好后，请选择你的答案。记住，只有一个正确选项！

**正确答案是：3. 用于对问题进行分类和过滤**

GitHub Issues 中的标签是组织项目的强大工具。它们可以让你快速识别问题的类型（错误、增强、问题）、优先级，或者问题影响项目的哪个部分。这种分类方式使得管理包含许多问题的大型项目更加轻松。

### 实践活动：创建一个 Issue

现在你已经了解了标签的用途，让我们来将这些知识应用到实践中：

1. 打开你的一个 GitHub 项目的仓库。  
2. 进入 "Issues" 标签页。  
3. 点击 "New Issue"（新问题）。  
4. 为你的问题起一个标题，内容可以是你想添加的功能或者你发现的一些错误。  
5. 在描述中提供问题的详细信息。记得要清晰简洁！  
6. 在右侧，你会看到添加标签的选项。为你的问题至少选择一个合适的标签。  
7. 提交问题。
