歡迎來到衝突峽谷，勇敢的程式員！在這片險惡的地帶，合併衝突隱藏其中，隨時準備挑戰即使是最有經驗的開發人員。但不要害怕，憑藉正確的工具和知識，你將能輕鬆克服這些障礙。

### 合併衝突的挑戰

想像一下，你正在與團隊合作一個項目。你負責更新項目的網站，但當你嘗試推送你的更改時，卻遇到了合併衝突。這正是你的技能將接受考驗的時候！

### 瞭解 GitHub 問題

在我們深入解決衝突之前，讓我們先來探討一個協作編碼中的關鍵工具：GitHub 問題（Issues）。這不僅僅是錯誤報告工具；它們還是整個項目的溝通中心。

### 提問：GitHub 問題中的標籤有什麼用途？

花點時間思考以下選項：

1. 將問題分配給團隊成員  
2. 設定問題的截止日期  
3. 將問題分類和篩選  

想一想你在項目中使用 GitHub 的經驗。你認為這些功能中哪一項與標籤的用途最契合？

當你準備好了，選擇你的答案。記住，只有一個正確選項！

**正確答案是：3. 將問題分類和篩選**

GitHub 問題中的標籤是一種強大的項目組織工具。它們可以讓你快速識別問題的類型（例如錯誤、功能增強、問題），問題的優先級，或者它影響項目的哪個部分。這種分類在管理包含大量問題的項目時尤其方便。

### 實作活動：創建一個問題

現在你已經瞭解了標籤的用途，讓我們把這些知識付諸實踐：

1. 打開你某個項目的 GitHub 存儲庫。  
2. 導航至 "Issues" 頁籤。  
3. 點擊 "New Issue"（新建問題）。  
4. 為問題設定一個標題，可以是你想新增的某個功能或注意到的錯誤。  
5. 在描述中提供有關該問題的詳細信息。請記住，清楚簡潔地描述！  
6. 在右側，你將看到添加標籤的選項。選擇至少一個適合的標籤來標記此問題。  
7. 提交問題。
