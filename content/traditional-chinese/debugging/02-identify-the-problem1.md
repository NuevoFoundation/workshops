## 編譯器錯誤

讓我們開始來看一下新手程式設計師面對的第一個令人望而生畏的問題之一：**閱讀**並**理解**錯誤訊息。

錯誤訊息主要有兩種類型：**編譯器**錯誤和**運行時**錯誤。

**編譯器**錯誤通常表示程式語法有問題。可能是你想在程式中表達某個想法，但未遵守程式語言的規則。這類錯誤會在你編譯程式時被發現。編譯器錯誤相對較容易修復，因為像 `gcc` 這樣的編譯器通常會提供有關錯誤發生原因的信息。我們來探討一些這樣的錯誤。

打開下面 Replit 程式中的 **Shell** 標籤，然後執行以下命令：

```bash
make CompilerErrors
```

{{% notice note %}}
在此示例中，我們不會執行此程式——此程式主要用於展示一些你可能會遇到的常見編譯器錯誤。
{{% /notice %}}

第一個錯誤應該看起來像這樣（或類似的）：

![錯誤 1：缺少分號](../resources/w2-01.png "一個編譯器錯誤的螢幕截圖，顯示 'error: expected ';' after top level declarator'")

你會注意到錯誤訊息包含以下內容：

- 嘗試編譯的檔案名稱 (**`CompilerErrors.c`**)。
- 發現錯誤的行號 (**`12`**)。
- 該行上錯誤發生的位置 (**`19`**)。

如你所見，編譯器提供了錯誤所在的程式碼行，並指出了錯誤實際發生的位置！然後它提供一個簡短的錯誤名稱——在這個例子中，編譯器期望在行末有一個分號 (**`;`**)。你可以簡單地添加分號來修復這個錯誤。

另一個錯誤提到缺少大括號 (**`}`**)，而程式碼中卻有結束的大括號沒有對應的起始大括號。這一錯誤的修復也相對簡單：可以在 `func()` 旁邊加上相應的大括號 `{`。

{{% notice warning %}}
缺少大括號經常是導致看似非常奇怪錯誤的原因。編譯器不擅長識別大括號應放的位置，因此如果你在包含一個標頭檔案時漏掉了大括號，整個程式可能會出現大量錯誤。幾乎在所有情況下，如果編譯器在你未撰寫的程式碼中輸出大量錯誤，原因大多是你（或甚至是該函式庫）的程式碼中某處漏掉了大括號！
{{% /notice %}}

修復之後，你可以使用相同的命令重新編譯程式：

```bash
make CompilerErrors
```

等等，錯誤還有更多！如警告提示框所述，如果缺少大括號，編譯器並不擅長發現所有錯誤。一個編譯器錯誤可能會「隱藏」其他錯誤。

我們將通過一個表格展示一些常見的編譯器錯誤及其一般發生原因。

| 錯誤 | 原因 | 一般修復方法 |
|---|---|---|
| 缺少分號 | 缺少分號。 | 添加分號 `;`。|
| 預期函式主體在函式聲明符後 | 缺少大括號 `{`，通常在函式主體宣告的前面。 | 添加大括號 `{` 到正確位置。 |
| 預期識別符或 '(' | 在大括號的上下文中，通常意味著你有多餘的懸空大括號 `{`。 | 刪除多餘的大括號，或在其後添加相應的 `}`。 |
| 重複定義... | 在程式碼的某處重複定義了一個變數。 | 重命名變數，或刪掉多餘的定義。 |
| 使用了未宣告的型別... | 編譯器無法找到你希望使用的型別的定義。 | 通常是 `#include` 指令有錯誤（因型別通常宣告於標頭檔案中）。確認是否有拼寫錯誤。 |
| 必須使用 `struct` 或 `enum` 標籤 | C 要求在引用結構/列舉型別時使用 `struct NAME_OF_TYPE` 或 `enum NAME_OF_ENUM`。 | 通常 C 開發者使用 `typedef` 敘述來避免總是鍵入 `struct` 或 `enum`，不過你自己也可以添加這些關鍵字。 |
| 無成員名稱... | 在你的 `struct` 中，未定義你嘗試訪問的字段名稱。 | 可能是拼寫錯誤，或者你尚未在 `struct` 中定義該字段。 |
| 型別不相容... | 你在混用型別，而在 C 中這是不允許的，除非使用顯式轉型。 | 檢查賦值是否正確，或使用顯式轉型來在編譯時解決錯誤。不過這可能會導致運行時錯誤。 |
| 引數型別不完整 | 如果一個函式返回 `void`，則不能將它作為引數傳遞給另一個函式！ | 修改函式聲明使其不返回 `void`，並確保這是你想要的行為。 |
| 多餘的 '(' 或 ')' 在 ';' 前 | 圓括號 `()` 不匹配 | 你有多餘的一組括號。
