## 第 1 部分：Config 變數

讓我們來了解一些 Phaser 的基本概念，一個使用 HTML 和 JavaScript 製作網頁遊戲的遊戲框架！這將是您在本次工作坊中學習的內容。

打開 `game.js`。每個 Phaser 遊戲都會以一個變數開始，此變數存儲遊戲的相關配置（通常像我們這樣命名為 config）。

```javascript
var config = {
  type: Phaser.AUTO,
  width: 512,
  height: 544,
  backgroundColor: 0x000000,
  scene: [Scene1, Scene2],

	physics: {
        default: 'arcade',
        arcade: {
            gravity: { y: 0 },
            debug: false
        }
    },
};
```

在這個變數中，您會注意到我們定義了遊戲的各種特徵，比如寬度、高度和背景顏色。我們還定義了將要使用的場景（稍後會有更多關於場景的介紹）。當然，您也可以在沒有場景的情況下創建遊戲，僅僅將所有代碼寫入 `game.js` 文件中。

您還會注意到，我們在 Config 中定義了遊戲的物理特性。在遊戲設計中，物理是定義遊戲“手感”的最重要方面之一。例如，《瑪利歐》中彈跳的物理特性，讓人能明顯感受到“這就是瑪利歐”。在我們的遊戲中，您可以看到我們使用了簡單易用的 Phaser 的“arcade”物理。此外，在我們的物理設置中，我們將重力設置為 0，因為我們的遊戲是一個太空射擊遊戲，我們不需要任何重力將角色拉向下方。

在 `game.js` 的結尾，可以看到我們將 config 變數傳遞給一個 game 變數，這也是 Phaser 遊戲中幾乎總是需要完成的事情。

## 第 2 部分：場景（Scenes）

現在，讓我們來聊一下場景。場景本質上是一種使用者所操作的遊戲狀態。通過一個例子來理解會更簡單：

讓我們來看看著名的遊戲系列《寶可夢》。當你玩遊戲時，通常會四處走動，探索世界。當你在草叢中遇到訓練師或野生寶可夢時，你會進入一個不同的場景以進行對戰。一旦完成對戰，你可能會打開地圖來查看接下來要去哪裡——這也是另一個場景。這三個場景的功能完全不同，並且各自有專屬的機制。當你關閉地圖後，遊戲會切換回到你以玩家身份漫遊的世界。而當你進入對戰時，遊戲又切換到對戰場景。您可以看到，創建這三種遊戲狀態的方式完全不同——對戰需要菜單，世界需要2D空間和一個玩家角色，地圖本質上則是一張互動圖表。我們將它們分成不同的場景，是因為這些場景的每個部分都需要用完全不同的方式來創建。

您可以將用戶想像成在各個場景間流轉進行遊戲。一個時間內他們只操作一個場景，而每個場景幾乎就像一個迷你遊戲（儘管通常會有一個主場景，其並不完全被算作“迷你”）。

{{% notice info %}}

從技術上講，如果您願意的話，我們可以將這三個遊戲狀態都放在一個場景中（如何將遊戲分割成場景由遊戲設計師決定）。理論上是可以這麼做的，但這樣會讓代碼變得非常複雜（在這種情況下，我甚至無法想像如何不堆疊視覺效果就把它們塞進一個場景內）。

{{% /notice %}}

以下是另一個使用場景的常見範例：標題畫面。

![Outliers game title screen](../media/title-game.png)

第一個場景通常僅顯示一個標題畫面，可能包含一些設置、讀取存檔等內容。一旦玩家點擊開始遊戲，他們將被切換至另一個場景，該場景內玩家將進行遊戲。

這正是我們將要實現的內容。場景 1 將包含一個標題畫面，而場景 2 則包含我們的實際遊戲內容。因此，場景 2 將包含大部分代碼，也是您將主要進行工作的地方。

# 第 3 部分：無限畫布（Infinite Canvas）

當您在 Replit 中啟動遊戲時，可以看到畫面上顯示一個空白畫布，這是您最終將放置遊戲內容的地方。然而，您所見的僅是畫布的某一部分——實際上，畫布在所有方向上都是無限大的。畫布的每個部分行為都相同——這意味著物件可以移動到或放置在使用者無法看到的畫布區域內。

這一點至關重要，因為對於我們的遊戲，我們不希望物件過多地超出螢幕。因此，我們需要將物件限制在螢幕內，或者在它們超出螢幕時將其刪除。
