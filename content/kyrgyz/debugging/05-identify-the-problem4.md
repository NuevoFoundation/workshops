## Катачылыктын башка түрү: Эстутумдагы каталар

C/C++ программаларынын түйшүгү, эстутумдагы каталар эң көйгөйлүү каталардын бири болуп саналат. Алар өз убагында чечилбесе, аныкталбаган иштерге (кайталангыс каталарга!) жана эстутумдун жоголушуна алып келет. Ошондуктан, мындай каталар менен күрөшүү эң жогорку артыкчылыкка ээ.

{{% notice note %}}

Эстутумдун жоголуусу сиздин программаңыз `malloc` же `calloc` (же башка эстутум бөлүштүрүүчү чакырууларды) чакырып, бирок эстутумду бошотпой койгондо болот. Эстутум "жоголот" - аны программа токтогонго чейин калыбына келтирүүнүн (оңой) жолу жок.

{{% /notice %}}

Бактыга жараша, адамдар эстутумдагы каталарды табуу үчүн атайын программаларды жазып чыгышкан, алардын бири - `valgrind`. Valgrind - бул инструмент, ал эстутумдагы маселелерди гана табуу менен чектелбестен, каталардын так кайсы жерде болгонун көрсөтүп берет. Келгиле, `valgrind` аркылуу эстутумдагы каталар кайда болуп жатканын көрөлү. Мисалы катары, биз C тилинде жасалган примитивдүү вектордун ишке ашырылышын колдонобуз, ал C++ стандарттык китепканасынын динамикалык массивинин версиясы болуп саналат.

<a class="my-2 mx-4 btn btn-info" href="https://replit.com/@nuevofoundation/Debugging-Samples-C" target="_blank">Replit'ти ачуу</a>

Программаны биринчи кезекте төмөнкү буйрук менен түзүңүз:

```bash 
make Vector
``` 

Андан кийин аны иштеңиз:

```bash
examples/Vector
```

"Double free" деп аталган ката бар экенин байкаңыз! Бул катанын түрү бир тилке дарегине эки жолу `free` чакыруу болгондо пайда болот.

Эми `gdb` ордуна, эстутум кантип бөлүштүрүлүп жана колдонулуп жатканын текшерүү үчүн `valgrind` колдонолу. Төмөнкү буйрукту иштетиңиз:

```bash
valgrind --tool=memcheck --leak-check=full examples/Vector
```

`valgrind` айрым каталарды тапканын көрүү жеңил болушу керек, балким булар "double free" менен байланышкан (төмөнкү `ERROR SUMMARY` бөлүмүндө каталар көрсөтүлгөнүн байкаңыз).

Айрым каталарды карап көрөлү.

![Valgrind ката 1](../resources/w4-02.png "Консоль катасынын скриншоту: 'Invalid read of size 8 at 0x484522D...' тексттери менен.")

Жогоруда көрсөтүлгөн ката мыйзамсыз окуу деп аталат, бул көбүнчө белгилүү бир эстутум тилкеси башка блокта бошотулганда пайда болот. `Valgrind` эстутумдун кайсы жерде бөлүштүрүлүп жана бошотулганын көрүүгө жардам берет:

![Valgrind ката 2](../resources/w4-03.png "Консоль катасынын скриншоту: 'Address 0x4b74040 is 0 bytes inside a block of size 16 free'd...' тексттери менен.")

Эстутум блок `createVectorInt` функциясындагы `malloc` аркылуу бөлүштүрүлгөн, аны `main` функциясы чакырган. Ал эми бул блок `pushBack` функциясындагы `free` аркылуу бошотулган.

Акырында, "heap summary’де" 96 байты жоголгондугун көрүүгө болот - башкача айтканда, эстутумдун жоголуусу болгон. Бул, себеби, биз `main` функциясынын аягында векторду өчүрүү үчүн `deleteVectorInt` чакырууну унутуп койгонбуз.

![Valgrind ката 3](../resources/w4-04.png "Консоль катасынын скриншоту: 'HEAP SUMMARY: in use at exit: 96 bytes in 2 blocks... 96 bytes in 2 blocks are definitely lost in loss record...' тексттери менен.")

`Valgrind` сиздин C жана C++ программаларыңыздагы эстутум каталарын табуу үчүн абдан көп маалымат берет. Ал сизге каталарды кайда болуп жатканын гана эмес, эстутум бөлуктөрүнүн кайда бөлүштүрүлүп жана кайда бошотулганын да (же бошотулбаганын, эстутумдун жоголуусуна алып келген учурда) көрсөтөт. Вектор мисалындагы мыйзамсыз окууларга эмне себеп болгон катаны таба аласызбы?

{{% expand "**Жоопту көрүү үчүн чыкылдатыңыз**"%}}
Байкаш керек, массивди кайра бөлүштүргөндө, биз `list->__arr` жаңыртууну унутканбыз! Бул бошотулган тилкеге жазуу болуп жатат дегенди билдирет, бул `Valgrind`де көрсөтүлгөн мыйзамсыз окуу жана жазуу каталарын, "double free" каталарын (анткени биз мурда бошотулган тилкеге кайрадан `free` чакырабыз) жана эстутум жоготууларын (жаңыланган массивдерге кайрадан эч качан шилтеме берилбегендиктен) туура түшүндүрөт! Болгону бул көрсөткүчтү жаңы жаңыланган массивге орнотуу керек, бул катаны оңдойт.
{{% /expand %}}
<br/>

Тапшырмаларда пайда болгон эстутум каталарын оңдоп чыгууңуз талап кылынат.
