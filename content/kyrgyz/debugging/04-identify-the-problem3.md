## Дебаггерлер

Кодду дебаг кылуу ошондой кеңири тараган жана жалпы көйгөй болгондуктан, башка программисттерге натыйжалуу дебаг кылууга жардам берүү үчүн бүтүндөй программалар түзүлүп келген. Бул программалар **дебаггерлер** деп аталат, жана C программалоо тили үчүн иштеген көптөгөн дебаггерлер бар. Бүгүн биз терминал менен колдонулуучу кеңири таралган дебаггерлердин бири `gdb` менен таанышып көрөбүз.

<a class="my-2 mx-4 btn btn-info" href="https://replit.com/@nuevofoundation/Debugging-Samples-C" target="_blank">Replitти иштетүү</a>

Мисалдар үчүн биз <a href="https://www.youtube.com/watch?v=SLauY6PpjW4" target="_blank">Quicksort</a> алгоритмин колдоном.

**Quicksort** алгоритми массивди иреттөө үчүн алгач массивдин элементтеринин бирин `pivot` катары тандайт.

Андан кийин элементтер төмөнкү шарттар боюнча уюштурулат:
- Pivotдон кичине элементтер.
- Pivotдон чоң элементтер.

Иреттөө бүткөндө, массивдин жогорку жана төмөнкү бөлүктөрүндө процесс рекурсивдүү түрдө чакырылып, pivot орто чекит катары алынып, иреттөө жүргүзүлөт.

{{% notice note %}}
Quicksortтун биздин версиясы сол жактагы эң чоң элемент "чоңураак" деп алынат, ал эми оң жактагы элемент partition ичинде pivot катары алына турганын болжолдойт.
{{% /notice %}}

|:--:|

[GDB (GNU Project Debugger)](https://sourceware.org/gdb/) күчтүү дебаггер болуп саналат, ал терминалдан дебаг кылууга мүмкүндүк берет, бул графикалык интерфейске (GUI) жетүү мүмкүн болбогон учурларда пайдалуу.

Программаны натыйжалуу дебаг кылуу үчүн анын иштөөсүн түшүнүү абдан маанилүү. Quicksortтун биздин ишке ашырылуусу рекурсивдүү түрдө Quicksortту аткарат жана учурдагы элемент pivotдон кичине болсо иреттөөнү жүргүзөт, ал эми биринчи элементти "чоңураак" деп эсептейт. Иреттөөнүн өзү `partition` функциясынын ичинде жүргүзүлөт.

### GDB менен дебаг кылуу этаптары
#### Программаны компиляция кылуу
1. **Shell** барагын ачып программаны компиляция кылуу:

```bash
make Quicksort
```

{{% notice note %}}
Программа компиляция болгондо `-g` жана `-Og` деген параметрлер колдонулат. Биринчиси компиляторго **дебаг маалыматтарын** кошууну айтат, бул параметрсиз gdb программаны дебаг кыла албайт. Экинчиси компиляторго программаны анын структурасын өзгөртпөй оптималдаштырууну кабарлайт. Эгерде `-Og` жок болсо, компилятор сиздин кодуңузду оптималдуу өзгөртүп ташташы мүмкүн, бул дебаггерди анча эффективдүү кылбайт.

Бул экинчи параметрдин маанилүүлүгүн эстен чыгарбаңыз. Дебаг кылуу үчүн компилятор сиздин кодуңузга **ШЕКСИЗ**  минималдуу оптималдашуулар колдонуп жатканын текшериңиз, анткени оптималдаштыруулар код иштеп жаткандагы өзгөрүүлөргө олуттуу таасир эте алат!
{{% /notice %}}

#### Программаны иштетүү 
1. Терминалда `gdb examples/Quicksort` командасын терүү. Бул GDB интерфейсин ачат. `gdb` менен программа дебаг кылуу үчүн `gdb <программанын аты>` командасын колдонсо болот.

2. GDB `Reading symbols from ./examples/Quicksort...` деп билдиргенине ишениңиз, болбосо сиз программаны GDBге тиркей албайсыз.

3. GDBден терминал командалык сабынан чыккандай `quit` (же анын кыскартылганы `q`) командасын киргизүү аркылуу чыгууга болот.

#### Программаны дебаг кылуу

Программаны дебаг кылуу үчүн аны GDBден иштетүү керек.

1. `run` (же `r`) командасын киргизүү. Бул программанын адаттагы терминалдан ишке киргендей эле ишке киришин камсыздайт.
```bash
(gdb) run
```

Программа алгач иреттелүүсү керек болгон массивдин мазмунун чыгарат: тартипсиз сандардын массивин. Андан кийин программа классификация алгоритмин ишке ашырып, акырында массивди иреттөөчү массив катары чыгарат. Сиз массивдин иреттелип жатканын көрө аласыз!

Бирок, көрүнүп тургандай, иреттөө күткөндөй ишке ашпай жатат.

Эми дебаггердин эң маанилүү жана кызыктуу куралынын бирин колдонобуз: **брокпоинттерди**. Брокпоинт деген программа аткарылып жатканда белгилүү бир код саптарына жеткенде токтоосун дебаггерге билдирүүчү чекит. Бул программанын ичинде эмне болуп жатканын реалдуу убакытта кароого мүмкүндүк берет. Белгилей турган нерсе, дебаггер токтогон линияны программаны улантканга чейин аткарбайт.
