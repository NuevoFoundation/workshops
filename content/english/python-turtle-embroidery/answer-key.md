### Activity 1

**Challenge: a closed blue square, sides of 80 screen units, with no center-to-start line.**

```python
import turtle

turtle.shape("turtle")
turtle.speed(3)
turtle.color("blue")
side = 80

turtle.penup()
turtle.goto(-60, -60)
turtle.pendown()

for edge in range(4):
    turtle.forward(side)
    turtle.left(90)

turtle.done()
```

The border is smaller than the 120-unit starting square. It closes because all four edges have equal length and all four turns are 90 degrees. It need not remain centered. `penup()` prevents a line from the origin to the first corner.

**Discussion answer:** `forward(80)` draws an entire edge on screen, but real stitches are discrete thread spans between needle penetrations. A stitch planner subdivides the edge. Screen units alone do not define its physical length. The turtle's turn changes its heading; it does not instruct the machine to rotate its needle.

### Activity 2

**Challenge: 20 mm between two 20 mm squares, with a 2 mm running-stitch target.**

```python
import turtle

turtle.speed(0)
turtle.color("black")
display_scale = 0.5

for start_x in (-250, 150):
    turtle.penup()
    turtle.goto(start_x * display_scale, -100 * display_scale)
    turtle.pendown()
    turtle.dot(3)
    for edge in range(4):
        for stitch in range(10):
            turtle.forward(20 * display_scale)
            turtle.dot(3)
        turtle.left(90)

turtle.done()
```

Paste this solution into Activity 2's embedded editor. The first right edge is `-250 + 200 = -50`. A 20 mm modeled gap is 200 units, so the second start is `-50 + 200 = 150`. The code keeps both side lengths at 200 model units (20 mm) and each step at 20 units (2 mm).

**Discussion answer:** moving from one square to the other must happen with the pen up so the model does not draw a connector. A real stitch plan would need a jump. Screen zoom or `display_scale` changes display size only; our chosen model still represents ten units per millimeter. A trim is a requested thread cut, not a guarantee a particular machine will perform it.

The result should show two separate squares marked with dots. No SVG/PES or real stitch pattern is generated by this Codebunga activity.

### Activity 3

**Challenge: a quarter-circle top arc, with the two side arcs unchanged.**

```python
import turtle

turtle.speed(3)
turtle.color("black")

def arc_at(x, y, heading, radius, extent):
    turtle.penup()
    turtle.goto(x, y)
    turtle.setheading(heading)
    turtle.pendown()
    turtle.circle(radius, extent)

arc_at(40, 40, 90, 40, 90)
arc_at(-60, 0, 180, 25, 180)
arc_at(60, -50, 0, 25, 180)

turtle.done()
```

Only the final argument of the first arc call changes. At the same radius, a 90-degree arc has half the length of a 180-degree arc. Its endpoint changes from approximately `(-40, 40)` to `(0, 80)`; the side curves remain half circles.

**Discussion answer:** lifting the pen prevents lines between independent curves. Positive radius puts the circle's center to the turtle's left, so resetting the heading is important when placing each arc.

### Activity 4

**Challenge: radius 25, unchanged overall width 180 and height 110, and a closed frame.**

```python
import turtle

turtle.speed(3)
turtle.color("black")
width = 180
height = 110
radius = 25

turtle.penup()
turtle.goto(-width / 2 + radius, -height / 2)
turtle.setheading(0)
turtle.pendown()

for pair in range(2):
    turtle.forward(width - 2 * radius)
    turtle.circle(radius, 90)
    turtle.forward(height - 2 * radius)
    turtle.circle(radius, 90)

turtle.done()
```

The horizontal straight sections become `180 - 50 = 130`; the vertical ones become `110 - 50 = 60`. Four quarter-circle corners still complete a full turn, returning the turtle to approximately `(-65, -55)`, facing right. The frame's bounds remain x = -90 to 90 and y = -55 to 55.

**Discussion answer:** full-length straight edges plus curves would add the corners' extra horizontal and vertical distances to the desired dimensions. Subtracting two radii from each straight-section length leaves room for the curves. Do not add an extra `left(90)` after `circle(radius, 90)`: the arc already changes the heading.

### Activity 5

**Challenge: purple eyes, black outline, then an all-black comparison.**

Use Activity 5's complete [browser drawing program](../media/nuvi_turtle_preview.py). Set its configuration to:

```python
OUTLINE_COLOR = "black"
EYE_COLOR = "#7b2cbf"
BLACK_EYES = False
```

These are replacement assignments in the supplied full program, not a standalone drawing. Press Run in Codebunga: the outline is black and both eyes are purple.

Next, change `BLACK_EYES` to `True` and press Run again. Both eyes now use the black outline color. `EYE_COLOR` remains purple but is deliberately not selected. Students should keep a copy of their favorite code before leaving the page.

**Discussion answer:** the drawing changes colors without physically changing thread. A real two-color embroidery plan needs a thread-change request before both eyes; the all-black design needs no change. Actual thread must still be prepared, and the browser's drawing settings do not update the original export script automatically.

**Shape and movement examples:** the face frame has straight edges; the body has rounded corners; side/top paths and oval eyes are curved; `draw_path()` lifts the pen before each independent part. The practice arcs are circular; the reference design's supplied control-point curves are more flexible. No exact stitch spacing is represented by the final browser curve sampling.

Any clothing choice is valid. Students do not need to provide personal information or bring clothing. Sharing the drawing and explaining the shape/movement choices completes the mission.
